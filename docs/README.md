## 各文档的边界

**README.md（根目录）** —— 唯一入口。产品定位、安装三步、快捷键、常见问题、
从源码跑、发布。GitHub 首页就是它，所以内容要能独立成立。

**使用手册.md** —— README 的展开版，给"要照着做"的人。操作步骤、界面说明、卸载清理。
不写技术原理。

**接口笔记.md** —— 唯一记录"接口怎么用、哪里会踩坑"的地方。实测数据带日期，
结论变了要**直接改**，不要在后面追加"补充：……"（那样三个月后就没人看得懂了）。

**环境说明.md** —— 只回答"这东西是什么、在哪、多大、能不能删"。

**目录结构.md** —— 文件夹职责 + 常用命令 + 命名约定。

**历史-Rust方案.md** —— 2026-10-21 的初版选型（Rust + egui），实际实现是 C#/WPF。
保留是因为里面"为什么走原生""为什么用 mpv""瓶颈在网页端不在网络"的判断仍然成立。
**代码相关的部分不要照着做。**

## 维护约定

- 结论有变 → 改原文，不留"过时但保留"的段落
- 涉及数字（体积、耗时、条数）→ 写实测日期
- 文档里出现的按键、路径、文件名 → 必须能在代码里找到对应的东西
  （2026-10-25 就因为文档还在教用户按 `L`/`U`/`R`，而这三个键早就不绑了）
- 新增功能先想清楚归哪份，不要三份都写一遍
