# 目录结构

> 原则：**源代码和文档跟着项目走；工具链和第三方代码放在固定的、不进版本库的地方。**

```
douyin-desktop-v2/
│
├─ README.md                 项目入口：是什么、怎么跑
├─ PLAN.md                   方案：为什么这么做、分几步
├─ .gitignore                哪些不进版本库
│
├─ docs/                     文档
│  ├─ 环境说明.md            装了哪些东西、在哪、能不能删
│  ├─ 目录结构.md            本文件
│  └─ 接口笔记.md            实测的接口、踩过的坑
│
├─ src/                      源代码
│  ├─ DouyinDesktop.sln          解决方案
│  ├─ DouyinDesktop.Core/        签名 + 接口 + 数据模型（没有界面，可单独测试）
│  ├─ DouyinDesktop.App/         界面（WPF）
│  ├─ DouyinDesktop.Player/      播放器（驱动 mpv）
│  └─ DouyinDesktop.Tests/       测试
│
├─ tools/                    开发期工具（不参与编译）
│  ├─ golden/                签名测试向量
│  │  ├─ gen_abogus_vectors.py   从参考仓库生成向量
│  │  └─ abogus_vectors.json     32 组基准数据
│  └─ probe/                 临时验证脚本（Python）
│
├─ scripts/                  一键脚本
│  ├─ env.ps1                激活环境（临时改 PATH）
│  ├─ setup.ps1              补齐缺的东西
│  └─ fetch-mpv.ps1          下载播放器
│
├─ assets/                   随程序发布的资源
│  └─ mpv/                   mpv.exe（120MB，不进版本库）
│
├─ env/                      项目专属运行时（不进版本库）
│  └─ python/                Python 虚拟环境，仅跑探针用
│
└─ vendor/                   第三方参考代码（不进版本库，只读）
   ├─ DouYin_Spider/         签名算法参考
   └─ douyin-desktop-v1/     第一版 Electron 应用
```

## 为什么这么分

### `src/` 拆成四个项目

不是为了好看，是为了**能单独测**。

签名算法是纯计算，不该依赖界面。拆成独立的 `Core` 之后，`Tests` 可以
在没有任何窗口的情况下验证签名对不对——这是整个项目最关键的一道关。

`Player` 单独拆，是因为它要跟一个外部进程（mpv.exe）打交道，
出问题的时候能立刻定位是"播放器坏了"还是"界面坏了"。

### `tools/` 和 `src/` 分开

`tools/` 里的 Python 脚本只在开发时用，最终发布的产品里一个都不包含。
混在 `src/` 里会让人误以为它们参与编译。

### `env/` 和 `vendor/` 不进版本库

- `env/python` 60MB，可以随时重建
- `vendor/` 8.5MB，是别人的仓库，克隆一份就够了
- `assets/mpv` 120MB，是二进制

这三样加起来 190MB，如果提交进 Git，仓库会变得又慢又难克隆。
`scripts/setup.ps1` 能一键把它们都恢复。

### 为什么 .NET SDK 不放在项目里

784MB，是**通用工具**，不是这个项目的私有依赖。
放进项目等于每个 C# 项目都多存 784MB。
`scripts/env.ps1` 会临时把它加进 PATH，用完就没了。

## 常用命令

```powershell
# 激活环境（点号不能少）
. .\scripts\env.ps1

# 编译
cd src; dotnet build

# 跑测试（签名校验）
cd src; dotnet test

# 运行
cd src; dotnet run --project DouyinDesktop.App

# 重新生成签名向量（需要 vendor\DouYin_Spider）
python tools\golden\gen_abogus_vectors.py --spider-dir vendor\DouYin_Spider --out tools\golden\abogus_vectors.json
```

## 命名约定

| 类型 | 规则 | 例子 |
| --- | --- | --- |
| 项目名 | `DouyinDesktop.<层>` | `DouyinDesktop.Core` |
| 签名相关类 | 保留逆向时的原始命名 | `ABogus`、`Z148Expand` |
| 业务类 | 正常英文 | `FeedService`、`AwemeItem` |
| 文档 | 中文，能看懂就行 | `环境说明.md` |

> 签名部分刻意保留 `L[23]`、`a98`、`z148` 这类原始命名，因为改名字之后
> 就没法和 Python 参考实现对账了。丑，但能查错。
