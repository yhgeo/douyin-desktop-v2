## 抖音 Rust 重构 — 方案规划

**任务**：基于抖音网页端，用 Rust 重构桌面客户端。V1 只需「能正常刷视频」。用户第一版 `yhgeo/douyin-desktop`（Electron 44 + 用户脚本注入）流畅度差。

**调研结论**：
- 第一版 AGENTS.md 取证质量高，已排除 `:has()` 样式重算（216ms→15.8ms）、`waitNode` 观察器、遮挡停帧（已用 `backgroundThrottling:false` 修）、`CalculateNativeWinOcclusion`（空操作）。
- **关键反证**：同一脚本在 Edge 流畅、Electron 卡 → 瓶颈在壳层而非网页端。
- 剩余嫌疑：① Electron GPU 进程异常 fallback 到 SwiftShader 软解（`app/main/lifecycle.js` 有 GPU 退出监听，说明遇到过）；② preload 重复注入（日志里 GM 菜单注册了 10 次）。
- `cv-cat/DouYin_Spider` 是爬虫，价值在 `utils/` 签名（a_bogus / dtrait）与 `dy_apis/` 接口，不含 UI 参考。

**方案**（详见 `PLAN.md`）：
- 阶段 0（0.5 天）：测 `chrome://gpu` 的 Video Decode + 播放时 CPU 占用 + 掉帧率，与 Edge 对照。决定后续路线。
- 阶段 1（3–5 天）：Tauri 2 + 系统 WebView2（本机已装 155.0.4283.62）。目标是**追平 Edge**，不是超越。
- 阶段 2：性能加固，复刻 `:has()` 门控，注入幂等化。
- 阶段 3（按需）：原生播放器 —— rquickjs 跑抖音 webmssdk 签名 + libmpv（`--wid` 子窗口 overlay）+ 推荐流 API。要「超越 Edge」只有这条路。

**已确认的技术前提**：
- Tauri 2 `WebviewWindowBuilder` 有 `initialization_script` 和 `additional_browser_args`（仅 Windows）。
- wry 在 Windows 上**总是把 initialization_script 注入所有子框架** → 脚本首行必须 `if (window.top !== window) return;`。
- WebView2 无同步 IPC（`GM_getValue` 同步读必须靠启动时把配置内联进注入脚本）。
- WebView2 不同 `additional_browser_args` 必须配不同 `data_directory`。
- 本机 **未安装 Rust**（`cargo` / `rustc` 均 not found），阶段 1 前需装 rustup + MSVC build tools。

**待用户决策**：是否先做阶段 0 验证；用户脚本是完整移植还是精简重写。

## 方案 v2：原生路线（上方 Tauri 套壳方案已作废）

**推翻原因**：用户实测 Edge 打开抖音网页加载视频同样要几秒 → 瓶颈在网页端自身，换渲染内核无用。**不使用抖音网页端**。

**已实测打通的数据链路（2026-10-21，游客态，无需登录）**：
| 环节 | 结果 |
| --- | --- |
| 游客态初始化（ttwid / s_v_web_id / challenge） | 成功，34 Cookie，2419ms（仅首次） |
| `/aweme/v1/web/module/feed/` | status_code=0，10 条，2395ms |
| `aweme/v1/play?video_id={uri}&ratio=1080p&line=0` | **302 → CDN → HTTP 206 + video/mp4 + ftypisom**，首包 216ms |
| 带宽 | 7.4 MB/s |
| 清晰度 | `ratio=1080p/720p` 均可用 |

**三个关键坑（已定位，勿再踩）**：
1. `video.play_addr.url_list` **已加密成 800 位 hex**，不要试图解密。用 `play_addr.uri` 走官方 `aweme/v1/play/` 接口换真实流地址。
2. `video.misc_download_addrs` 里虽有明文 CDN URL，但实测 **403（Lego Server）**，那是下载场景，别用。
3. 推荐流响应结构已变：`aweme_list` 为空，真实数据在 **`cards[].aweme`，且是 JSON 字符串**，需二次解析。DouYin_Spider 的 `get_feed` 未适配。

**「几秒」的归因**：网络层首包 216ms + 3MB 用 404ms ≈ 0.6s 就能出画面。网页端的几秒全花在 React 挂载 / 埋点 SDK / 播放器实例化 / 广告位 / 风控组件上，原生端这些一个都没有。

**TLS 指纹非必需**：把 curl_cffi 换成普通 requests，推荐流仍返回 status_code=0。V1 用普通 `reqwest` 即可；风控升级再换 `wreq`（0.16.1 活跃维护，BoringSSL，需 cmake/clang）。

**架构**：egui（UI）+ mpv（`--wid` 嵌入，硬解）+ dy-sign（签名）+ dy-api（数据）。流畅度来自**预取**：一次取 20 条 → 并发预取后 3 条 → 稳态切换 0 等待。

**净移植量**：约 1600 行 Python → 约 1200 行 Rust（ab_pure 369 + mstoken 368 + fingerprint 332 + header/params 430）。绕开 `login_api.py` 3412 行（V1 游客态够用）。

**已完成**：
- `PLAN.md` 重写为 v2 原生方案
- `tools/golden/gen_abogus_vectors.py` + `abogus_vectors.json`：**32 组 a_bogus golden 向量，覆盖全部 4 个 counter 桶及边界，两次生成逐字节一致**。签名长度 192。
- 关键细节：`sign_query` 内部先 `counter += 1` 再分桶，故实际分桶值是 counter+1；同桶内签名完全相同（唯一 26/32 属正常）。

**环境缺口（阻塞下一步）**：Rust 未装；**MSVC 未装**（vswhere 无输出，`Program Files (x86)/Microsoft Visual Studio` 只有 Shared）。需装 VS Build Tools（C++ 桌面开发，约 2–3GB）。mpv 也未安装（需打包便携版）。
